# Plan — Rust TUI editor: a headless-testable editing core

## 1. Goal and scope

Build a full-screen terminal editor whose **editing logic is testable without a terminal**. The
thing being measured is the document model: offsets, lines, grapheme clusters, undo groups, search
matches and a save round-trip that reproduces bytes. A renderer that cannot be tested is a
renderer that hides bugs, so the plan puts a pure view model between the document state and
`ratatui`, and the TUI layer stays thin enough that everything it decides is already covered by a
test elsewhere.

No text leaves the host and nothing is fetched at runtime: the same commands on the same file
produce the same bytes, the same cursor and the same transcript on every run.

### Final functionality

- a workspace of three crates: a core library with **no terminal dependency**, a thin TUI binary,
  and a headless harness binary that emits the same commands the keymap emits;
- a declared buffer structure (gap buffer over UTF-8 bytes) with insert, delete-range and line
  access, and a declared cost shape asserted by measurement;
- a cursor expressed as `(line, grapheme column)` over extended grapheme clusters, with a declared
  sticky column, clamping rules and an anchor/head selection;
- command-based undo and redo with run grouping, no clock, a bounded stack and a save point;
- literal forward search with wrap, an ASCII-only case-folding rule and match navigation;
- file open, save and save-as with UTF-8 validation, a declared newline classification, a UTF-8 BOM
  policy, an atomic write and a visible error path for an undecodable file;
- an exhaustive `Command` enum, a declared keymap table per mode, and a pure frame view model with
  byte-exact snapshots;
- a per-milestone test suite plus a committed script/transcript pair for the vertical slice;
- `verify.sh` producing `verify.json` for every milestone id, headless from start to finish.

### Non-goals

Syntax highlighting, plugins, LSP, tree-sitter, multiple panes, tabs, multiple open files, mouse
input, OS clipboard integration, config files, word movement, regex search, soft line wrapping,
auto-indent, session persistence, a GUI toolkit, deployment and packaging. The TUI is **not
launched** by any verification step: `verify.sh` builds it, asks it for `--version`, and never lets
it take over a terminal or an alternate screen.

## 2. Locked technical decisions

```text
Language:   Rust, edition 2021, stable toolchain, no nightly features
Packages:   one Cargo workspace, three crates: editor-core, editor-tui, editor-headless
Core deps:  unicode-segmentation only (extended grapheme clusters, UAX #29)
TUI deps:   ratatui + crossterm in editor-tui only; editor-core has no terminal crate
Offsets:    byte offsets at UTF-8 char boundaries, never inside a scalar value (§ 5)

Undo:       inverse-command groups, no clock, UNDO_DEPTH = 1000 groups
Search:     literal, single line, ASCII-only case folding, wrap on
Newlines:   '\n' internally, remembered convention re-emitted on save (§ 9)
Render:     view::frame(state, width, height) -> Vec<String>, pure, no terminal crate
Tests:      cargo test; no terminal, no window, no network, no wall-clock in library code
Determinism: library code reads no clock and no random source; tests use a declared LCG
```

The clock appears in exactly one place in the whole project: the two cost-shape measurements of
§ 12 M1, inside their test. It never influences a command, a byte written or a frame.

The boundaries are the seams the tests use:

- `editor-core` is a library: `Editor::apply(Command)` mutates state and returns
  `Result<(), EditorError>`. It never reads the environment, never formats anything for a human
  beyond the view model, never touches `stdin`, `stdout` or the filesystem except through an
  explicit path argument.
- `buffer` owns the bytes and the line index and is the only place where a byte enters or leaves
  the document. `cursor`, `selection`, `undo` and `search` work on top of it and never re-implement
  line splitting.
- `view` turns state into `Vec<String>` and is the only place that decides layout. It is pure: same
  state and size, same strings, no `ratatui` type in its signature.
- `editor-tui` is thin: parse arguments, build a `Key` from a crossterm event, look the key up in
  the keymap, call `apply`, draw the frame strings. Every decision it makes is delegated, so the
  bytes it would write are already covered by a test.
- `script` maps one script verb to one `Command` and formats one transcript line, with no terminal
  and no clock; `editor-headless` is a `main` that reads a file and prints what `script` returns, so
  the transcript the tests compare in-process is the transcript the binary prints. A harness verb
  that has no `Command` counterpart is a bug, and one test asserts the verb table and the command
  enum agree.
- Dependencies point one way: `editor-tui → editor-core`, `editor-headless → editor-core`,
  `editor-core → unicode-segmentation`. No crate depends on another crate's internals.

## 4. Vertical slice and the headless harness (M0)

The slice is the whole editorial path — **open a file, modify it, undo, redo, save, reopen with the
correct content** — driven entirely through commands, with no terminal in the process. It is the
only milestone whose omission blocks everything else, and its evidence is a committed script and a
committed byte-exact transcript.

### Harness contract

`editor-headless <script> [--workdir <dir>]` reads one command per line and writes one transcript
line per script line, in order, to `stdout`. Relative paths resolve against `--workdir` (default:
the process working directory). Exit code `0` when every line was accepted, `2` when the script
itself is malformed; a rejected command is a transcript line, not an exit code. The parser and the
transcript writer live in `editor_core::script`, which has no terminal, no clock and no `stdin`, so
the binary is a shell over tested code and the tests can compare transcripts in-process.

| verb | meaning |
|---|---|
| `open <path>` | `Command::Open` |
| `save`, `save-as <path>` | `Command::Save`, `Command::SaveAs` |
| `insert <text>` | `Command::InsertStr`; `\n`, `\t`, `\\` are the only escapes |
| `newline` | `Command::InsertNewline` |
| `backspace`, `delete` | `Command::DeleteBackward`, `Command::DeleteForward` |
| `move <motion> [extend]` | `Command::Move`; motion ∈ `left right up down line-start line-end doc-start doc-end` |
| `select-all`, `collapse` | `Command::SelectAll`, `Command::CollapseSelection` |
| `undo`, `redo`, `break` | `Command::Undo`, `Command::Redo`, `Command::BreakUndoGroup` |
| `search <query>`, `search-input <text>`, `search-accept`, `search-next`, `search-prev`, `search-cancel` | the search commands of § 8 |
| `state` | prints one `state` line (below), no mutation |
| `dump` | prints one `dump` line (below), no mutation |
| `quit` | `Command::Quit`, ends the script early |
| `# …` | comment, no transcript line |

Transcript lines, exactly:

```text
ok <verb>[ <argument>]
err <verb> <kind>
state modified=<0|1> line=<1-based> col=<0-based> lines=<n> sel=<none|a..b> undo=<groups> redo=<groups> nl=<lf|crlf|mixed|none> bom=<0|1>
dump len=<bytes> text="<escaped>"
```

`err` kinds: `io`, `decode`, `no-path`, `query`, `boundary`. `sel=a..b` reports the selection as
byte offsets in document order. `nl=none` means the document contains no newline at all. `dump`
escaping (`EDUMP`): `\n`, `\r`, `\t`, `\\` and `\"` are escaped; other characters in
U+0000–U+001F and U+007F are written `\u{XX}`; every other character, including non-ASCII, is
written as itself. A `dump` line therefore states the exact byte content, including a missing
trailing newline.

## 5. Buffer contract (M1)

The document is UTF-8. The buffer stores it as bytes behind a **gap buffer**: two byte runs with a
movable gap between them, plus a line index (the byte offset of the start of every line). The
structure is declared here because it decides the cost of every edit, and the chosen structure must
be justified in one file comment at the top of `buffer.rs`. A rope is an accepted alternative; both
pass the tests of this section, because no test asserts the storage layout.

### Operations

```rust
insert(&mut self, at: Offset, bytes: &[u8]) -> Result<(), BoundaryError>
delete(&mut self, range: Range<Offset>) -> Vec<u8>          // returns the removed bytes
line(&self, n: usize) -> Option<Range<Offset>>              // content of line n, newline excluded
line_of(&self, at: Offset) -> usize                         // index of the line holding `at`
lines(&self) -> usize                                       // count of lines, always >= 1
len(&self) -> usize                                         // byte length
as_bytes(&self) -> &[u8]                                    // the whole document, for save and dump
```

- An `Offset` is a **byte offset at a UTF-8 char boundary**. `insert` and `delete` reject an offset
  inside a scalar value with `BoundaryError { at }` and change nothing. This is the rule that makes
  partial-UTF-8 corruption impossible rather than merely unlikely.
- `lines()` counts line breaks plus one: the empty document has 1 line, `a\nb` has 2 lines,
  `a\nb\n` has 3 lines, and the last line of the last case is empty. `line(n)` never includes the
  terminating `\n`, so concatenating every `line(n)` with `\n` between them reproduces the document
  except for a possible trailing `\n`, which `lines()` plus `as_bytes()` disambiguates.
- `'\n'` is the only line break in the document; a `'\r'` is an ordinary character inside a line
  (§ 9 explains how a CRLF file is normalised on open).
- `delete` returns the removed bytes so the undo layer of § 7 can build an inverse edit without a
  second read of the buffer.

### Cost shape, asserted

Two measurements, both inside `m1_buffer.rs`, both checking **shape** and not a ranking between
implementations or hosts:

```text
COST_INSERT_PREFIX_N  = 1_000_000   single-byte inserts at offset 0 into an empty buffer
COST_INSERT_PREFIX_MS = 5000
COST_LINE_ACCESS_N    = 100_000     lines built, then line(i) called twice for every i
COST_LINE_ACCESS_MS   = 5000
```

A `String`-or-`Vec<u8>` buffer that shifts the tail on every insert moves about
`10^6 × 5·10^5 = 5·10^11` bytes for the first measurement; a buffer without an index rescans
`10^10` bytes for the second. A gap buffer with a line index answers both in well under a tenth of
each budget on a slow host, which is why the budgets are generous: the assertion is that the
structure is not accidentally linear per edit, not that it is fast.

### Test obligations

- insert and delete at every char boundary of every fixture, compared against a `String` reference
  model written in the test;
- `BoundaryError` on every offset inside a multi-byte character, with the buffer unchanged (`dump`
  equal before and after);
- `line`, `line_of` and `lines` for the empty document, LF-only, CRLF-normalised, and a document
  with no trailing newline;
- a randomised differential test: 1 000 sequences of 200 random edits over a fixed alphabet
  (ASCII plus one 2-byte, one 3-byte and one 4-byte character), driven by
  `Lcg::new(seed)` with the declared constants `6364136223846793005` and `1442695040888963407`,
  asserting the buffer equals the reference model after every edit;
- the two cost-shape measurements, each printing its own elapsed value on failure.

## 6. Cursor and selection contract (M2)

A cursor is `(line: usize, col: usize)`: `line` is 0-based internally and reported 1-based, `col`
counts **extended grapheme clusters** from the start of the line, 0-based. Grapheme clusters come
from `unicode-segmentation`, so `e` + U+0301 is one column, and a ZWJ family emoji is one column and
four or more chars. Cursor-to-offset conversion is the only bridge between grapheme columns and byte
offsets:

```rust
cursor_to_offset(&self, c: Cursor) -> Offset
offset_to_cursor(&self, at: Offset) -> Cursor      // a boundary inside a cluster maps to that cluster's start
```

`cursor_to_offset` is total: a column past the end of a line clamps to the line end. The two are
inverse for every in-range cursor — `offset_to_cursor(cursor_to_offset(c)) == c` for every
`c = (line, col)` with `col` at most the line's grapheme count — and a clamped cursor comes back
clamped, which is the declared behaviour rather than a broken round trip.

### Motion rules

| command | rule |
|---|---|
| `Move(Left)` | with a selection: collapse to its start, no motion. Otherwise one grapheme left; at column 0 and not the first line: end of the previous line. At the document start: no change. |
| `Move(Right)` | with a selection: collapse to its end. Otherwise one grapheme right; at the line end and not the last line: column 0 of the next line. At the document end: no change. |
| `Move(Up)` / `Move(Down)` | keep the sticky column, clamp to the target line's length; the first line up and the last line down do not move. |
| `Move(LineStart)` / `Move(LineEnd)` | column 0 / the line's grapheme count. |
| `Move(DocStart)` / `Move(DocEnd)` | `(0, 0)` / the last byte's line and its grapheme column. |
| `Move(m, Extend)` | the same motion with the head moved and the anchor kept; an absent anchor is set to the pre-motion head, so the first extended motion always selects exactly the span it crosses. |

The **sticky column** is the column the cursor would return to if the lines were long enough. It is
set to the current column by every horizontal motion, by every edit and by `CollapseSelection`, and
it is preserved by `Move(Up)` and `Move(Down)` only. This is the rule that makes `Down` through a
short line and back land on the original column, and it is asserted as such.

### Selection

A selection is `anchor` plus `head`, both cursors. `selection()` is `None` when they are equal, so
an empty selection does not exist as an object. `range()` normalises: `start = min(anchor, head)`,
`end = max(anchor, head)`, and `extend_forward` is `head > anchor` — the three together are the
declared normalisation, and a `Move(Left, Extend)` past the anchor therefore flips direction
instead of producing an inverted range.

Editing a selection replaces it: `Insert`, `InsertStr`, `InsertNewline`, `DeleteBackward` and
`DeleteForward` first delete `range()` and then act at `start`, in **one** undo group. `DeleteForward`
on an empty selection at the document end and `DeleteBackward` at offset 0 are no-ops, not errors.

### Test obligations

- a declared motion table over fixtures containing ASCII, combining marks, ZWJ emoji, CJK, tabs and
  an empty line, one case per rule above, including the collapse-on-motion rules;
- `Left`/`Right` never split a cluster: on `e` + U+0301 one `Right` lands at column 1 and a
  second at column 2, so the two scalar values are one cursor step;
- sticky column: from a long line, `Down` into a short line and `Down` again returns to the original
  column; a horizontal move resets the sticky column;
- clamping at both document ends and on every short line of the fixture set;
- selection normalisation: anchor/head order, direction flag, `range()` in document order, and the
  replace-on-edit rule under all five editing commands;
- `offset_to_cursor(cursor_to_offset(c)) == c` for every in-range `c` of every fixture, and
  `cursor_to_offset` after a delete that removes the cursor's own line.

## 7. Undo and redo contract (M3)

Undo is command-based: every accepted editing command contributes primitive edits, and the undo
layer stores the inverse of each group. Redo re-applies the same edits. There is no snapshot of the
whole document per group, and no clock anywhere.

### Grouping (declared, clock-free)

A group is **a contiguous run of the same edit family**, closed by anything else:

1. `Insert`, `InsertStr` and `InsertNewline` are one family; `DeleteBackward` and `DeleteForward`
   are another. Two families never share a group.
2. The new edit must start where the group's last edit ended (insertions) or end where it started
   (backward deletions) — a gap in the span closes the group. Typing `abc` is one group; typing
   `a`, moving the cursor, typing `b` is two.
3. Any non-editing command (`Move`, `Select*`, `Undo`, `Redo`, `Save`, `SaveAs`, `Open`, `Search*`,
   `CollapseSelection`) closes the open group, and so does `BreakUndoGroup`.
4. A group holds at most `GROUP_MAX_OPS = 256` primitive edits; the 257th starts a new group, so a
   long paste-like run of inserts is bounded in memory.

Consequences that are asserted rather than promised: typing five characters then `Undo` removes all
five; `InsertStr("hello")` then `Undo` removes `hello` in one step; delete-then-insert at the same
offset are two groups.

### Stack, save point and reporting

- `UNDO_DEPTH = 1000` groups. When the 1001st group is pushed the **oldest** group is dropped and
  its inverse is lost — undoing past that point stops, it does not corrupt.
- A new edit **clears the redo stack**; so does `Open`.
- Each group records the pre-group cursor and selection, and undo restores them exactly. Redo
  restores the post-group cursor and selection.
- `save_point` is the undo-stack depth recorded by the last successful `Save`. `modified()` is
  `undo_depth() != save_point`, so undoing back to the saved state reports unmodified and redoing
  forward from it reports modified. When a group is dropped by `UNDO_DEPTH`, the save point becomes
  unreachable and `modified()` reports true until the next save; that is the declared behaviour and
  is tested by shrinking the limit through the `limits` module in a test-only build.
- `undo_depth()` and `redo_depth()` are public and appear in the harness `state` line, because
  grouping is measured through them and never through the internal stack.

### Test obligations

- a declared scenario table: one row per grouping rule, each with the command sequence, the
  resulting byte content and the expected `undo`/`redo` depths;
- contiguous typing groups and a cursor move splits the group (§ 7 rules 2 and 3);
- `InsertStr` is one undo step; `InsertNewline` merges with a contiguous insert;
- redo invalidation: undo twice, edit once, `redo` is a no-op and `redo_depth()` is 0;
- bounded depth: 1 001 edits with `UNDO_DEPTH` reduced to 10 in the test build, then 10 undos work
  and the 11th is a no-op, and `modified()` reports true;
- save point: type, save, edit, undo → unmodified; redo → modified; undo past the save point →
  modified;
- cursor and selection restoration on undo and redo, including a selection-replacing edit;
- undo and redo of edits touching multi-byte characters and a grapheme cluster boundary.

## 8. Search contract (M4)

Search is literal, linear and single-line: a query is matched inside each line separately, so a
query containing `\n` is `Err(QueryError::Multiline)` and an empty query is
`Err(QueryError::Empty)`. There is no regex and no word matching.

- **Folding**: `case_sensitive: bool`, default `false`. Insensitive matching folds **ASCII
  `A`–`Z` only**; every other character is compared byte-exactly. Consequence, declared and tested:
  `É` does not match `é`, while `ABC` matches `abc`.
- **Occurrences**: within a line, matches are found left to right and **non-overlapping**, so
  `aa` in `aaaa` matches at columns 0 and 2 and not at 1.
- **Order and shape**: `matches()` returns every match in document order as
  `Match { start: Offset, end: Offset, line: usize, col: usize, len_chars: usize }`, where `col` is
  the grapheme column of `start` and `len_chars` counts Unicode scalar values. A match that begins
  inside a grapheme cluster is reported at the cluster that contains it, and is selected by offsets
  rather than by columns.
- **Navigation**: `SearchNext` selects the first match whose `start` is greater than the current
  cursor offset; if none exists and `wrap` is true (default) the first match of the document is
  selected; with no match at all the status message is `no match` and the cursor stays.
  `SearchPrev` is the mirror image. Selecting a match sets the selection to its span and the cursor
  to its `end`.
- **Prompt mode**: `SearchOpen` enters `Mode::Search` and records the *search origin* (cursor and
  selection). Every `SearchInput(char)` recomputes matches and selects the first match at or after
  the origin, wrapping; the status row shows the prompt of § 10. `SearchAccept` keeps the selection
  and returns to `Mode::Normal`; `SearchCancel` restores the origin and returns to `Mode::Normal`.
  `SearchBackspace` removes the query's last character and recomputes; an empty query in prompt mode
  selects nothing and shows the prompt with no counter.
- Search never modifies the document, contributes no undo group and closes no save point.

### Test obligations

- a declared match table: single occurrence, repeated occurrence, non-overlapping occurrence,
  occurrence at column 0 and at the line end, one match on every line, no match, and a query longer
  than the line;
- ASCII folding both ways (`ABC` finds `abc`, `abc` finds `ABC`), and `É`/`é` and `İ`/`i` **not**
  matching, so the folding rule is the declared one;
- wrap and no-wrap for `SearchNext` and `SearchPrev`, from the first match, from the last and from
  a cursor past every match;
- multiline and empty queries rejected with their error kinds and no state change;
- a differential test: 1 000 random documents and queries from the declared LCG, compared against a
  naive `windows()` scan written in the test;
- prompt mode: incremental selection, accept keeps the selection, cancel restores the origin, and
  no undo group is created by any search command.

## 9. File I/O contract (M5)

### Decoding on open

`open(path)` reads the file once and validates it as UTF-8 in a single pass. On an invalid sequence
it returns `Err(EditorError::Decode { offset })`, where `offset` is the index of the first byte that
cannot begin or continue a valid sequence; the buffer, cursor, selection, undo stacks and path are
**unchanged** — an open either replaces the whole editor state or changes nothing.

A leading UTF-8 BOM (`EF BB BF`) is stripped from the document on open and recorded as `bom = true`;
saving re-emits it. A BOM anywhere else is an ordinary character.

### Newlines

The document holds `'\n'` only. On open the file's newline classification is recorded:

| classification | meaning |
|---|---|
| `lf` | the file contains at least one `\n` and every `\n` is bare |
| `crlf` | the file contains at least one `\r\n` and every line break is `\r\n` |
| `mixed` | both bare `\n` and `\r\n` appear |
| `none` | the file contains no line break |

A lone `\r` that is not followed by `\n` is **not** a line break: it stays inside the line as an
ordinary character, so an old-Mac file opens as one long line. `crlf` files are normalised to `\n`
in the document.

On save the classification decides the bytes: `lf` and `none` write `\n`; `crlf` writes `\r\n` for
every internal `\n`; `mixed` is written as `\n` and the status message says `newlines normalised to
LF`, so a mixed file is normalised deliberately and visibly rather than silently. The save of a
`crlf` file created from a `crlf` file is therefore byte-identical, which is the round-trip property
this section promises.

### Saving

- `save()` with no path is `Err(EditorError::NoPath)` and the status message is `error: no file
  name`. `save_as(path)` writes to the new path and adopts it, keeping the newline classification
  and the BOM flag.
- Writes are **atomic**: the encoded bytes go to `<file>.<pid>.tmp` in the same directory, are
  flushed and `sync_all`ed, and are then renamed over the target. An interrupted save leaves the
  original file untouched and the temporary file behind, which is the declared failure mode.
- A write failure (missing parent directory, permission denied) is `Err(EditorError::Io { path,
  kind })`, the document stays modified and the status shows `error: <kind>`.
- On success the save point is updated (§ 7), `modified()` is false and the status message is
  `saved`.

### Round-trip property, asserted

For every fixture the classification is declared in the test and the following holds: `open` then
`save` with **no edits** reproduces the file byte for byte, and `dump` before and after the save is
identical. The property covers: an empty file, an ASCII LF file, an ASCII CRLF file, a file with no
trailing newline, a BOM + CRLF file, a file whose content is NFC and NFD forms of the same word, a
file with combining marks, ZWJ emoji, CJK and a tab, and a file containing a lone `\r`.

Fixtures are **generated** by `tests/support/mod.rs` from declared byte literals into a `tempfile`
directory, never committed as bytes: a checkout with `core.autocrlf=true` would otherwise rewrite a
CRLF fixture and turn the round-trip test into a test of the checkout. That reason is written in a
comment next to the builder.

### Test obligations

- the round-trip property above, per fixture, byte for byte;
- invalid UTF-8 fixtures (`0xFF`, a truncated 3-byte sequence, a lone continuation byte, `ED A0 80`
  from the surrogate range) each reported with the exact byte offset and no state change;
- newline classification for all four cases, including a file with `\n` only and a file with `\r\n`
  only, and a mixed file whose save is `\n` with the normalisation message;
- BOM preserved, BOM stripped from the document, and a mid-document `EF BB BF` kept as a character;
- save-as adopts the path and re-saves identically; save with no path reports `no-path`;
- an atomic-write failure into a missing parent directory leaves the original file byte-identical
  and reports `io`;
- a save of a document with multi-byte characters reports the byte length of the written file and
  the content reopens identically.

## 10. Commands, keymap and view model (M6)

### Commands

```rust
pub enum Motion { Left, Right, Up, Down, LineStart, LineEnd, DocStart, DocEnd }
pub enum Extend { None, Extend }
pub enum Mode { Normal, Search }

pub enum Command {
    Move(Motion, Extend), Insert(char), InsertStr(String), InsertNewline,
    DeleteBackward, DeleteForward, BreakUndoGroup,
    SelectAll, CollapseSelection,
    Undo, Redo,
    Save, SaveAs(PathBuf), Open(PathBuf),
    SearchOpen, SearchInput(char), SearchBackspace, SearchAccept, SearchCancel,
    SearchNext, SearchPrev,
    Quit,
}
```

`Editor::apply(&mut self, cmd: Command) -> Result<(), EditorError>` is the only mutating entry
point, and it is what the harness, the tests and the TUI all call. `Command` is exhaustive: adding a
behaviour means adding a variant, so the keymap, the harness verb table and the frame tests all
fail to compile or fail a test until they are updated together.

### Keymap as data

The keymap is one declared table per mode, not a `match` inside the event loop:

```text
NORMAL   Left/Right/Up/Down      Move(m, None)      Shift+same     Move(m, Extend)
         Home / End              Move(LineStart|LineEnd, None)
         Ctrl+Home / Ctrl+End    Move(DocStart|DocEnd, None)
         Backspace / Delete      DeleteBackward / DeleteForward
         Enter                   InsertNewline
         Tab                     Insert('\t')
         Ctrl+Z                  Undo              Ctrl+Y, Ctrl+Shift+Z   Redo
         Ctrl+A                  SelectAll         Esc                   CollapseSelection
         Ctrl+S                  Save              Ctrl+F                SearchOpen
         F3                      SearchNext        Shift+F3              SearchPrev
         Ctrl+Q                  Quit              any other char key    Insert(that char)
SEARCH   Esc                     SearchCancel      Enter                 SearchAccept
         F3 / Shift+F3           SearchNext / SearchPrev
         Backspace               SearchBackspace   any other char key    SearchInput(that char)
```

`keymap(mode, key) -> Option<Command>` is a pure lookup over that table. A key with no binding is
ignored, silently: there is no bell and no error state. Declared unbound commands are exactly
`SaveAs`, `Open` and `BreakUndoGroup` — there is no path prompt and no clipboard in this plan, so
they are reachable from the harness and the library only. One test asserts the bound set, the
unbound set and the absence of duplicate bindings, so the table is checked rather than described.

### The view model

`view::frame(state: &Editor, width: usize, height: usize) -> Vec<String>` returns exactly `height`
strings of exactly `width` grapheme columns each — the last row is the status or prompt row, the
others are document rows. It uses no terminal crate and no clock, so it is snapshot-tested byte for
byte.

Layout, declared:

```text
gutter_width = max(GUTTER_MIN_WIDTH=3, decimal digits of the last visible line number) + 1 space
document row = right-aligned line number in the gutter, then the line's graphemes, tab = TAB_WIDTH=4 spaces
               a line past the end of the document is drawn as the empty text after the gutter
               a control character other than tab is drawn as '?'
               a row longer than the remaining cells is truncated at the cell boundary, no ellipsis
scroll         vertical: the cursor's line is always visible; scroll_line is the first visible line
               horizontal: the cursor's grapheme column is always visible; the first drawn column is
               scroll_col, and both offsets are part of the state so the frame is a pure function
status row     '<name>' + ('*' if modified) + ' L<line>/<lines>:C<col>' + (' ' + message if any)
               name is the file name, or '[no name]' when there is no path
search row     '/' + query + (' <index>/<total>' if any match else ' no match')
               drawn instead of the status row while Mode::Search; an empty query is just '/'
```

`scroll_line`, `scroll_col` and the status message are fields of the editor state, updated by the
commands that cause them; the frame function itself never computes a scroll position, so a snapshot
test does not depend on how the TUI got there.

The TUI layer maps each returned string to a `ratatui` `Line` and draws the block; the event loop
is `read event → Key → keymap lookup → apply → frame → draw`. That loop is deliberately the only
untested code in the project, and it is untested because it decides nothing: § 12 M6 asserts that
every decision it delegates to has its own test.

### Test obligations

- keymap coverage: every declared binding resolves to its declared command; no key is bound twice
  in one mode; the unbound command set is exactly `{SaveAs, Open, BreakUndoGroup}`; a `Char` key
  without a modifier maps to `Insert` in `Normal` and `SearchInput` in `Search`; a page-down key
  maps to nothing;
- frame snapshots, byte for byte, for: an empty document at 10×5; a three-line document with the
  cursor on line 2; a gutter that grows from 3 to 4 digits; a selection drawn across a line
  boundary; a status row with and without a path and with and without `*`; a search row with
  `1/3` and with `no match`; a tab, a CJK character, a combining mark and a control character in
  the text; a row truncated at the right edge; a frame whose height is 1 (status row only) and
  whose width is below the gutter width (declared: the text area gets zero cells);
- purity: the same state rendered twice yields identical strings, and rendering does not change
  `modified`, the undo depth or the cursor;
- isolation: a test reads `include_str!("../Cargo.toml")` and asserts that `editor-core`'s
  `[dependencies]` section contains no `ratatui` and no `crossterm`, so a terminal crate cannot
  enter the core without deleting the test;
- the TUI binary is built and answers `--version` with `rust-tui-editor <version>` and exit 0
  **before** any terminal initialisation, which is the only way verification touches it.

## 11. Test suite requirements

Seven integration targets in `crates/editor-core/tests/`, one per milestone, each runnable on its
own so an id maps to one exit status:

| target | covers |
|---|---|
| `m0_slice.rs` | the `script` module, the committed transcripts of § 4, the slice path end to end |
| `m1_buffer.rs` | § 5: operations, boundaries, line access, differential test, cost shape |
| `m2_cursor.rs` | § 6: motion table, grapheme clusters, sticky column, selection |
| `m3_undo.rs` | § 7: grouping table, redo invalidation, bounded depth, save point |

| `m5_io.rs` | § 9: round trip, decoding, newlines, BOM, atomic write, save-as |
| `m6_view.rs` | § 10: keymap coverage, frame snapshots, purity, crate isolation |

Rules that apply to all of them:

- tests assert **external behaviour** — buffer content via `dump`/`as_bytes`, cursor, selection,
  undo and redo depth, match spans, frame strings, written bytes. No test asserts a field or a
  private function of the buffer, so a rope implementation of § 5 passes unchanged;
- fixtures come from `tests/support/mod.rs`; the LCG of § 5 seeds every randomised test, so a
  failure is reproducible from the seed printed in the message;
- every table row names its own case in the assertion message, so a broken table is readable from
  the failure line;
- no test opens a terminal, starts a thread that reads `stdin`, or binds a socket;
- the editable document of a test is created in a `tempfile::TempDir`, never in the repository.

## 14. Operating instructions for the development agent

- Work one milestone at a time and keep the slice transcript green after each one. M0 is the only
  milestone whose omission blocks everything else.
- Write the test of a milestone before its implementation. Keep `editor-core` free of `stdin`,
  `stdout`, terminal crates and clocks: a leak there breaks the headless property, which is exactly
  what this benchmark watches for.
- Never assert the internal layout of the buffer. Assert bytes, cursor, selection, depths, matches
  and frames — the behaviour a user of the library can see.
- Keep the line index in one place. A second line-splitting routine in `search` or `view` is how the
  trailing-newline case gets missed.
- Never change a declared constant — `UNDO_DEPTH`, `GROUP_MAX_OPS`, `TAB_WIDTH`,
  `GUTTER_MIN_WIDTH`, a cost budget, a folding rule, a status format — to make a test pass. If a
  declared constant is wrong, say so and stop: the constants are the specification.
- When the slice transcript differs, diff the transcript before the file. A wrong `state` line and a
  wrong byte on disk are different bugs and never share a fix.
- Keep the TUI thin: parse, translate a key, apply, draw. A decision in the event loop is a decision
  the tests cannot see.
- Report, before declaring a milestone done: changed files, commands run, test results, the slice
  transcript and residual risks.
