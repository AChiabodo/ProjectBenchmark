# Constraint banner

Testo canonico del banner di vincolo, nelle due varianti IT ed EN a contenuto
identico. È il file a cui ogni `PLAN.md` si conforma: nessun Plan parafrasa il
banner per conto proprio, lo riporta **verbatim** come primo contenuto del file.
`scripts/index.mjs --check` estrae la variante corretta in base a
`spec_language` del `meta.json` e ne verifica la presenza letterale nel Plan.

- progetti esistenti (piani in italiano) → variante IT;
- progetti nuovi (piani in inglese, da C10) → variante EN;
- wording source (T1) → nessun banner: sono prompt prodotto e restano intatti.

Blocchi obbligatori (identici nelle due varianti): una sessione/un host/turni
di chiarimento; niente rete a runtime; dipendenze build-time pinnate; Compose
oltre un nodo; fuori scope deploy/publishing/CI; `./verify.sh` non interattivo
+ `verify.json`; `RESULT.md` con wall-clock, turni e token. Nessun tetto
wall-clock o di token: si registrano, non si impongono.

## Variante italiana

<!-- constraint-banner:it:begin -->
> **Banner di vincolo — condizioni non negoziabili della sessione**
>
> - Una sessione, un host: nessun intervento umano di design; al massimo 3 turni di chiarimento con l'operatore.
> - Nessuna richiesta di rete a runtime: niente API esterne, asset remoti o servizi; ogni risorsa è locale o generata dal codice.
> - Dipendenze build-time ammesse solo se pinnate (lockfile, oppure tag + hash).
> - Più di un nodo (FE/BE/DB/worker) ⇒ un profilo Docker Compose che sale con un solo comando.
> - Deploy, hosting, publishing, CI e release automation: fuori scope, non valutati.
> - `./verify.sh` è non interattivo, termina entro 600 s, exit 0 = pass, e scrive `verify.json` con tutti gli id milestone del `meta.json`.
> - `RESULT.md` è obbligatorio: modello, wall-clock, turni, token e verdetto dell'harness.
> - Nessun tetto wall-clock o di token: si registrano, non si impongono.
<!-- constraint-banner:it:end -->

## English variant

<!-- constraint-banner:en:begin -->
> **Constraint banner — non-negotiable conditions for this session**
>
> - One session, one host: no human design intervention; at most 3 clarification turns with the operator.
> - No network requests at runtime: no external APIs, remote assets or services; every resource is local or generated by the code.
> - Build-time dependencies are allowed only when pinned (lockfile, or tag + hash).
> - More than one node (FE/BE/DB/worker) ⇒ a Docker Compose profile that starts with a single command.
> - Deployment, hosting, publishing, CI and release automation: out of scope, unscored.
> - `./verify.sh` is non-interactive, finishes within 600 s, exit 0 = pass, and writes `verify.json` with every milestone id from `meta.json`.
> - `RESULT.md` is mandatory: model, wall clock, turns, tokens and the harness verdict.
> - No wall-clock or token cap: they are recorded, never imposed.
<!-- constraint-banner:en:end -->
